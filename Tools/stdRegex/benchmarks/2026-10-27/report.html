Regex performance trade-offs

Sihlfall beats ASF for Test and replacement. The old COM engine is faster on reused matching. ASF's faster capture-returning API has a different output cost.

Excel 16.0 build 20618 · x64 · Intel Core i7-9700KF. Eight patterns, four operations, three implementations, two independent workbook runs.

100 captured records: MatchAll takes 175 ms with Sihlfall, 177 ms with old stdRegex, and 31 ms with ASF. Both stdRegex versions create dictionaries; ASF returns lighter collections.

Replace those records: Sihlfall takes 1.98 ms, old stdRegex 0.025 ms, and ASF 37.4 ms.

Compatibility: ASF fails the word-boundary and numeric-backreference probes. Incorrect outputs are excluded from timing comparisons.

Method, interpretation, and limits

All timing samples were accepted only after output checks: the expected Boolean for Test, every numbered capture and match count for MatchAll, or the complete replacement string. Both word-boundary and backreference probes fail on ASF, producing eight excluded cells per run. The exact known Office-crashing issue 141 pattern was not executed in the old engine; the safer ^(ab)\1$ probe was used.

QueryPerformanceCounter measures inside VBA, excluding Excel automation calls. Each cell is warmed and calibrated to at least 30 ms per batch, up to 16,384 iterations, followed by five timed batches. The complete experiment was repeated in a separate workbook run; the tables show medians of the resulting ten batch averages per call, not individual-call latency percentiles. Engine order rotates between workload/operation cells.

Fresh construction plus first Test includes the first search because VBScript compiles lazily; constructor cache hits are excluded. Other operations reuse preinitialized objects. Shared static initialization is warmed before timing. Normal wrapper work and intermediate result disposal are included.

Capture output is an important confounder. The migrated and old stdRegex APIs create dictionaries, whereas ASF returns collections. In a separate five-batch diagnostic, constructing 100 comparable containers without any regex work took 67.2 ms for dictionaries and 0.311 ms for collections. The diagnostic discards each container before creating the next, whereas real MatchAll retains all results, so it is not an exact decomposition of MatchAll cost or proof that ASF's matcher is faster.

The migration is a compatibility/reliability choice, not a performance upgrade over VBScript. Short validation Test calls took about 17 µs for Sihlfall versus 4.7 µs for old stdRegex and 165 µs for ASF. Unanchored 1,024-character scans took Sihlfall about 1.1 ms versus the old engine's 0.005 ms and ASF's 25–26 ms. Match-result construction is a separate optimization target.

Native processing limits were raised to 2,147,483,647 to prevent accumulated ASF replacement budgets from distorting repeated runs. The old engine has no matching budget. These small representative inputs do not test pathological backtracking, and the results are specific to this computer. Background load and COM allocation vary; table tooltips show batch ranges and individual run medians.

Source versions: migrated stdRegex 04e7d04, sihlfall/vba-regex 1619cd7, old stdRegex abf14dd, ASF 290ad3e. The existing 78 compatibility assertions passed before each benchmark. Temporary Excel access and debugger settings were restored; test processes were closed.
